# 提议：指数看板

- 状态：提议中（阻塞：本地暂无指数日 K 数据）
- 日期：2026-11-19
- 范围：backend + frontend

## 1. 目标

做一个指数看板页面，固定展示以下指数的**基本行情信息**与**日 K 图**：

| 展示名 | 建议系统代码（thscode） | instruments | 当前日 K |
|--------|-------------------------|-------------|----------|
| 上证指数 | `000001.SH` | 已有 | **无** |
| 深证成指 | `399001.SZ`（「深证指数」按成指理解） | 已有 | **无** |
| 创业板指 | `399006.SZ` | 已有 | **无** |
| 科创综指 | `000680.SH` | 已有 | **无** |

> 说明：用户原文「创业扳指」按「创业板指」理解；「深证指数」默认映射为深证成指 `399001.SZ`；科创默认用科创综指 `000680.SH`（备选科创50 `000688.SH`）。定稿前可再确认。

## 2. 现状与阻塞

- 标的主数据：启动已载入 `instruments` 内存缓存；上述 4 只指数在 `market/instruments/instruments.parquet` 中存在。
- 日 K：当前 `market/ohlcv/1d/a_share_daily_k_1d.parquet` 约 5580 只 **A 股股票**，**不含指数**。因此看板无法出图。
- 图表库：前端已依赖 `lightweight-charts`，仓库内尚无封装/页面使用。
- 行情 API：日 K 仅有内存缓存，尚无按 symbol 的 HTTP 接口。

**结论：在补齐指数日 K 之前，本功能停留在提议阶段，不进入实现。**

## 3. 方案概要

### 3.1 数据层（先决条件）

1. 经扶摇（THS）拉取上述指数日 K，写入系统 canonical Parquet（与现有 OHLCV schema 一致：`symbol, trade_date, open, high, low, close, volume, amount, adjust, vendor, currency`）。
2. 存储可选：
   - **A（推荐）**：与股票合并进同一 `a_share_daily_k_1d.parquet`（或扩展为更中性的文件名），启动时统一 `load_ohlcv_1d_into_memory()`；
   - **B**：独立 `index_daily_k_1d.parquet`，启动时额外加载并合并进同一内存字典。
3. `vendor` 统一为 `ths`（扶摇仅为 HTTP 网关）。

### 3.2 后端 API

建议首版提供聚合接口（看板专用，减少前端请求次数）：

```http
GET /api/v1/market/index-board
```

响应形态（示意）：

```json
{
  "items": [
    {
      "symbol": "000001.SH",
      "name": "上证指数",
      "trade_date": "2026-11-18",
      "open": 0,
      "high": 0,
      "low": 0,
      "close": 0,
      "prev_close": 0,
      "change": 0,
      "change_pct": 0,
      "volume": 0,
      "amount": 0,
      "bars": [
        {
          "time": "2024-01-02",
          "open": 0,
          "high": 0,
          "low": 0,
          "close": 0,
          "volume": 0
        }
      ]
    }
  ]
}
```

约定：

- 指数清单由后端常量/配置维护（与前端解耦）。
- `change` / `change_pct` 相对前一交易日收盘价计算。
- `bars` 默认最近 **250** 个交易日（可后续加 `limit` 查询参数）。
- 某指数无日 K 时：`bars=[]`，基本字段可为空，前端显示「暂无行情」。

可选拆分（后续）：

- `GET /api/v1/instruments/{symbol}`
- `GET /api/v1/ohlcv/1d/{symbol}?limit=`

### 3.3 前端页面

- 路由建议：`/market/indexes`（侧边栏「常规」增加「指数看板」）。
- 布局：桌面 **2×2** 卡片；窄屏纵向堆叠。
- 每张卡片：
  - **基本信息**：名称、代码、最新价、涨跌额/涨跌幅（红涨绿跌或按产品统一配色）、当日 OHLC / 成交量（可选精简）。
  - **日 K**：`lightweight-charts` Candlestick（+ 可选成交量副图）。
- 数据：React Query 请求 `index-board`；与标的列表相同，开发期走 Vite `/api` 代理。

### 3.4 非目标（首版不做）

- 实时分时 / 分钟线
- 指数成分股列表
- 自选编辑看板标的
- 多周期切换（可放 P2）

## 4. 分阶段

| 阶段 | 内容 | 依赖 |
|------|------|------|
| P0 | 指数日 K 拉取、入库、进入启动内存缓存 | 扶摇行情接口与权限 |
| P1 | `index-board` API + 前端 2×2 看板 | P0 |
| P2 | 区间切换、单指数大图、与标的页联动 | P1 |
